# HVAC Data — v0.15.0

Open **FFE-pyRevit → MEPTools → HVAC Data** in a Revit 2025 or 2026 project. Reload pyRevit after installing or renaming the command so its ribbon label updates.

The modeless window displays host-model Spaces, including unplaced and zero-area Spaces. The initial columns are Level, Number, Name, Area, and Height. Height is `Space.UnboundedHeight`, not an average from volume/area. Measurements use Revit project units; sorting uses raw numbers. Space numbers remain text, including leading zeros.

Space phases are read from `ROOM_PHASE_ID`, falling back to `ROOM_PHASE`, using `AsElementId()`. The general element `CreatedPhaseId` is not used for Space phase filtering. If neither parameter resolves to a project phase, the row remains visible under All phases with a warning.

## Working with the table

Right-click a column header or a column group's band and choose **Change color…**. Pick a fill and click **Apply**; **Cancel** or Escape discards the draft. A group color fills its band, member headers, and data cells. Individual column colors override their group's fill; **Reset color** removes that override, or removes the band fill when used on the group. Text switches between black and white for contrast, and selected rows retain their selection highlight. Colors survive Refresh, header moves, and group edits, and are included in Save/Save As. Color changes mark the layout as unsaved and do not write to Revit until Save.

Saved-table controls occupy the left side of the header; Column groups, Parameters, Sync Spaces, and Refresh stay on the right. All header buttons share a 30px height, 12px text, and matching padding. The saved-table controls wrap on smaller windows.

- Click **Parameters…** to open a searchable window listing a checkbox, parameter name, Revit data type, and parameter type for every parameter found across the host model's Spaces. Parameter type distinguishes **Built-In**, **Shared Parameter**, and **Project Parameter**, with **Global Parameter** when encountered and **Other** when the origin cannot be identified. The catalog includes unset parameters. Definitions with the same name remain separate and show their parameter IDs.
- Toggle **Show checked only** to filter the list to the current draft selections, including locked starter columns. It combines with search by name, data type, parameter type, or ID. Unchecking an editable item removes it from the filtered list immediately. Toggling the filter does not change selections, and the toggle stays set while this window is open and reopened.
- Parameters already displayed in the table are checked when the picker opens. The five starter columns stay checked and locked; Phase reflects whether All phases is selected. Matching uses built-in IDs, so a custom parameter with the same name is still independent. Check additional columns and click **Apply** to add them, or uncheck them and Apply to remove them. **Cancel** or Escape discards the draft. The header checkbox selects or clears editable parameters in the currently filtered list.
- Revit formats selected parameter values; numeric values sort numerically, Yes/No values display as Yes/No, and references display the formatted value or referenced element name when available. Missing/unreadable values display an em dash. Ordinary Refresh preserves selected parameter columns for this window; reopening starts with the five starter columns.
- Choose a Phase and Level, or search by number, name, level, or phase. The initial phase matches the launching view; views without a phase use the last project phase. All phases reveals a Phase column.
- Click column headers to sort. Ctrl+click or Shift+click another header adds sorting. The first selected column has priority **1**, the next **2**, and so on; each later column breaks ties in the earlier columns. Subscripts beside the active arrows show those priorities when multiple columns are sorted. Changing a direction keeps that column's priority. Removing a sort renumbers the remaining columns; adding it again puts it last. The numbers disappear for single-column or cleared sorting. Drag headers to reorder columns and drag column edges to resize.
- Click **Column groups…** to create named bands above related column headers, for example **Dimensions** above Area and Height. Choose **Add header group**, enter a name, and check its columns. Each column belongs to at most one band. **Apply** moves the selected members together at their first member's position; **Cancel** or Escape discards the draft. Edit names/membership or use **Remove group** to ungroup its columns. A band can contain one or more columns, including added parameters; hidden Phase is labeled in the editor and stays hidden until All phases is selected.
- Within a band, drag leaf headers to reorder them. Dropping a leaf onto a column in another band moves it into that band; dropping onto an ungrouped column moves it out. Bands preserve column widths, sorting, selection, filters, and row grouping. Refresh retains available members and removes empty bands when parameters disappear. Save/Save As includes band names and memberships.
- Drag a band's title to move the entire column group before or after another band or an ungrouped column. The insertion marker shows the destination. All members move together, including hidden columns, with their order and settings preserved. Dropping onto a child of another band places the group beside that whole band. Canceling a drag leaves the layout unchanged; Save/Save As retains the new group order.
- Drag displayed column headers into the dashed grouping area above the grid, including added parameter columns. Each header adds a level: **Level → Name → Number** groups first by Level, then by Name within each Level, then by Number. Ordered chips and arrows display that hierarchy. Dropping the same column again never creates duplicate levels.
- Drag a grouping chip before or after another chip to change hierarchy order; focus a chip and press **Alt+Left/Right** for the same action. Click a chip's **×** to remove only that level, or **Clear all** to return to the flat table. Header-to-header drops still reorder columns. Canceled drags preserve the layout.
- Each nested group shows its own column, formatted value, and Space count. Click its header or focus its button and press Enter/Space to collapse or expand it. Grouping uses raw values and element identities, so zero, missing values, leading-zero numbers, and different elements remain distinct; missing values use **No value**.
- The full hierarchy stays selected through Refresh and filtering and is included when saving a table. Chips identify same-named parameter columns by ID. Removing a grouped parameter or hiding Phase removes only that level and retains the remaining hierarchy. Sorting, filtering, row selection, and Revit navigation remain available while grouped; keyboard row navigation skips descendants of collapsed groups.
- Click rows to toggle selection; Shift+click selects a range. Focus the grid and use Up/Down, Home/End, and Space for keyboard selection. Changing filters clears selections hidden by the new filters.
- **Select in Revit** changes Revit's selection. **Show in Revit** asks Revit to locate selected Spaces in an available view. Unplaced Spaces have no viewable geometry and are skipped; individual row warnings explain unavailable values.
- **Refresh** reloads model data while preserving valid filters, column sorting/order/widths, and selected rows. **Clear filters** returns to the snapshot's default phase, All levels, and an empty search.
- Model edits, undo, and redo mark the table **Out of date**. They do not automatically replace its rows. Deleted or replaced Spaces are checked again before navigation.
- Each document has its own independent window, which can go behind Revit and appears in the taskbar/Alt+Tab. Reopening the command focuses that model's existing window. Activate the corresponding model before using its Refresh, Select, or Show actions. Closing the document closes its table.

The warning panel reports unreadable and skipped rows. Space values remain read-only. Saved-table and Space-group actions write model metadata; browsing, filtering, grouping, refreshing, and navigation do not modify the model. There is no linked-model collection. Table browsing works offline. Sync Spaces is the entry point for Loadwise access.

## Named Space groups

Click **Space groups** beside Select in Revit to create a named set such as West wing or Offices. Selecting rows first prechecks those Spaces in a new group. Enter a name, search/check members across the entire model (including other phases), then click **Save group**. **Use table selection** replaces the membership with the table's currently selected visible rows. **Select listed** and **Clear listed** apply only to the editor's search results. Spaces may belong to several groups.

Choose a saved group to edit its name or membership. Closing or switching groups discards unsaved edits. **Delete group** requires a second **Confirm delete** click and only removes the definition. Unavailable members remain visible by UniqueId so you can remove or retain them. Same-named groups remain independent and show ID suffixes. Refresh after Reload Latest to see teammates' group changes.

Groups are model metadata, independent of table layouts and visual row grouping. Save/Sync Revit to persist/share them. Each group has its own DataStorage record under schema `aacb3874-e9c6-4c70-8cec-746c8118c0c6` (`FFEHVACSpaceGroupsV1`), with stable Space UniqueIds, a revision and author/timestamp. Edits check worksharing ownership, central status and the revision again after checkout; failures retain your draft. Read-only models can browse existing groups and use them for sync. Group names and membership stay in Revit; Loadwise receives every instance/type parameter for the selected Spaces, regardless of visible table columns.

## Autodesk Forma project connection

When HVAC Data opens for a Forma/Autodesk Docs cloud model, it reads the model's Data Management project ID and looks up its Loadwise project in the background. An existing project connects automatically. A missing project offers **Start project**; **Yes** creates the shared project, and **No** continues local browsing. Project setup does not send Spaces. Coworkers and other models in the same Forma project reuse the same Loadwise project by Forma ID.

The name comes from the named Autodesk cloud path. If Revit supplies no readable name, the tool asks for the name shown in Forma after you choose Yes. It never substitutes Revit Project Information's name. Matching uses the Forma ID. A lookup failure never triggers project creation. Close and reopen HVAC Data to retry lookup. Non-cloud files choose a Loadwise project in **Sync Spaces**.

A model already connected to a Loadwise project can associate that project with Forma. Conflicting connections stop with a warning. The retired v2 model UUID is not a project binding; it is ignored after the Loadwise database reset.

## Sync Spaces to Loadwise (FFE Mechanical)

1. Click **Sync Spaces**, choose a project, and leave **All Spaces** checked or clear it and select named groups. Click **Collect Spaces**. The host reads all instance and type parameters for the chosen host-model Spaces across phases/levels, including unplaced and zero-area Spaces. Table columns, filters and row selections do not limit parameter capture. Overlapping group members upload once. Collection creates a local preview without cloud writes.
2. Review the Space list and parameter counts; expand **Parameters** on a row to inspect all captured values, including hidden columns. Same-named definitions remain distinct using deterministic identity suffixes; built-in instance names keep priority for coordination field matching. Double values use Revit project display units, Yes/No values are booleans, and ElementIds stay exact strings. A double without measurable type metadata is labeled Revit internal units; failed display-unit conversions are reported as unavailable. Unset values are null; unreadable/unsupported values are null with an Unavailable display label and warning. Text longer than the API's 2,000-character limit is truncated with a warning. A Space whose parameter collection cannot be read is skipped and reported.
3. Confirm **Sync Spaces** to upload full snapshots to Loadwise's **Revit coordination dataset** using `push_revit_spaces`. Each selected Space's stored parameter map is replaced by this snapshot. Load calculation inputs and HAP/Excel data remain managed in Loadwise; this workflow now uses the full-parameter endpoint instead of the limited `sync_revit_spaces` load-room adapter. No Revit Space values are modified.
4. Requests are sent in batches of 200 with a single frozen sync ID. Only a complete, ungrouped scan finalizes missing-Space detection. Group-only or incomplete scans leave unselected Spaces' values and missing status unchanged. A complete project snapshot can flag previously uploaded Spaces from other models in that project as missing; no Spaces are deleted. Empty pushes and missing/ambiguous/wholly unavailable selected groups are rejected instead of falling back to all Spaces. The API accepts up to 2,000 parameters per Space and 5,000 catalog definitions per sync.
5. The preview identifies chosen groups, excluded/unavailable Spaces and collection warnings. If Revit or group membership changes before confirming, collect again. **Retry sync** resumes the failed batch using the same frozen payload and sync ID; previously confirmed batches are retained. If a response was lost after the database applied a batch, its repeated values are unchanged. Counts can reflect that repeat. The result reports created/updated/unchanged Spaces, parameter values, batches, skipped Spaces and unavailable parameters. Use **Reload projects** to change groups.

The first confirmed sync stores the **Loadwise project ID** on Project Information using schema `711c7777-907c-4c60-9ea7-35e7567465de` (`FFEHVACLoadwiseProjectV1`). **Save/Sync Revit** to persist and share this connection. First-time binding needs an editable model and Project Information checkout; a bound read-only model can reuse its connection. Binding is saved before HTTP and remains if the network request fails. Space parameters are never modified.

FFE-Mechanical owns the schema and API under `supabase/migrations` and `supabase/API.md`. This command requires **API v3**, introduced by `20261124000600_loadwise.sql`. That migration resets the application's old cloud data; updating pyRevit does not run migrations. Use the database setup procedure in FFE-Mechanical. Full-parameter sync additionally requires the additive **20261125000700_coordination.sql** migration. The command bundles its IronPython-compatible v3 client, full-parameter adapter and Forma helper, using the shared publishable key without individual sign-in and the Revit user name for attribution. HTTPS runs on a worker thread; document collection and metadata transactions run in the ExternalEvent context.

## Shared saved tables

- Start with **Unsaved table**, configure a view, and choose **Save** or **Save As…** to create a named definition in this model. The **Table** dropdown opens definitions already stored in the project. Opening a definition collects current Space data rather than a stored copy of its values.
- Save captures parameters, column order/widths, named header bands, sort order, row grouping, phase, level, and search. Row selections, expanded/collapsed groups, window size, and parameter-picker display toggles remain temporary. Each tool launch starts with the five starter columns until you choose a saved table.
- **Unsaved changes** appears when the working layout differs from its saved definition. Switching tables or closing the tool offers **Save**, **Discard**, or **Cancel**. A failed save retains your working view and stops the pending switch/close. If Revit has already closed the document, its table closes without attempting a storage write.
- **Save** updates the selected shared definition. **Save As…** creates an independent definition. **Rename…** changes only its name, preserving both stored settings and unsaved working changes. **Delete…** removes the shared definition after confirmation and leaves your current view open as an unsaved table. Same-named definitions remain independent and have distinct labels in the dropdown.
- **Reopen** explicitly reloads the selected saved definition and current Space values, with Save/Discard/Cancel for unsaved work. Use it after Reload Latest to reconcile a shared definition changed by another user.
- **Save/Sync the Revit project** to persist and share definition changes. Teammates receive them through normal Reload Latest/Sync. **Refresh** updates the tool's catalog from the currently loaded model; it does not automatically perform Reload Latest or replace a working layout with a teammate's settings.
- A read-only model can open saved definitions but cannot save, rename, or delete them. An owned, centrally updated, or revision-conflicting definition rejects an update and retains your edits. Reload Latest and reopen the definition to reconcile changes, or use Save As to keep a separate working copy.
- Built-in IDs, shared GUIDs, project definition UniqueIds, and phase/level UniqueIds identify saved settings. Parameters are never substituted by name alone. Missing settings produce warnings and a modified working view: unavailable columns are omitted, dependent sorting/grouping is cleared, and missing filters use initial defaults. The stored definition changes only if you explicitly Save the repaired layout.

## Architecture and dependencies

The native WPF host owns a WebView2 control and a queued Revit `ExternalEvent` bridge. The browser receives structured JSON snapshots; it never receives Revit objects. This pushbutton's `lib/revit_data_table.py` owns data collection, request validation, and navigation. Its `lib/ffe_webview2.py` adapts Keynotes' tested assembly compatibility loader without changing Keynotes. The command adds its own `lib` directory to the import path. Snapshots union the definitions in each Space's `Parameters` collection; only selected extra columns have values read and serialized while browsing. Sync uses the separate `lib/revit_parameters.py` collector to capture every instance/type parameter without adding columns to the table. Applying a selection performs a validated refresh through the same external-event bridge, without modifying the model.

`lib/saved_tables.py` validates/restores layouts and stores one versioned JSON definition per `DataStorage` element using Extensible Storage schema `7d601ebb-ff8a-4268-9ba7-145ea9a2f03c` (`FFERevitDataTableV1`). Reading does not create storage; the schema is registered on the first explicit save. Each definition has a UUID, revision, name, author, UTC timestamp, and layout. Version 4 JSON includes optional six-digit hex `color` values on columns and `headerGroups`, stable member identities, and ordered `groupFields` for row grouping. Versions 1 through 3 remain readable and are upgraded only on an explicit save/rename. The schema's string field is unchanged. Older tool versions reject newer definitions instead of silently dropping settings. Writes use short transactions, an actual worksharing checkout for existing elements, central-update checks, and a revision comparison after checkout. Failed writes roll back. Corrupt or unsupported definitions are reported without being rewritten. `support/saved_tables.js` manages working-view state, dialogs, and dirty-state tracking; `support/header_groups.js` edits header band drafts; `support/header_colors.js` owns the color context menu and fills.

Tabulator **6.3.1** is pinned and bundled under `support/vendor`; runtime loading is fully offline. The source files are the published `tabulator-tables@6.3.1` package's `dist/js/tabulator.min.js`, `dist/css/tabulator.min.css`, and `LICENSE`, downloaded from jsDelivr. Keep `LICENSE.tabulator` when updating the assets. No Node/npm installation or frontend build is required for users.

WebView2 browser data lives under `%LOCALAPPDATA%\FFE-pyRevit\RevitDataTable\WebView2`. The loader reuses compatible loaded SDK assemblies, otherwise preferring pyRevit's runtime-specific pair before Revit's pair. Initialization errors report versions/paths. Fully restart Revit after changing SDK/add-in installations; reloading pyRevit cannot replace already-loaded DLLs.

## Validation

From the `RevitDataTable.pushbutton` directory, with CPython 3 and Node 22+:

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/*.test.cjs
node tests/revit_data_table_browser.cjs
```

All table-specific tests live in this pushbutton's `tests` directory and run separately from repository-level test discovery. The Python loader tests reuse the shared Keynotes fixture at the repository's `tests/test_keynote_webview2.py`.

The browser test uses installed Microsoft Edge headlessly with a simulated Revit bridge and no npm dependencies. Set `EDGE_PATH` to override the executable path. It writes a screenshot to a temporary browser profile. It validates browser behavior; actual Revit integration requires the local [acceptance checks](tests/revit_data_table_acceptance.md).
