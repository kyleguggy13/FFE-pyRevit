# HVAC Data acceptance checks

Run in both Revit 2025 and Revit 2026 with the installed extension and supported pyRevit IronPython engine. These checks require an actual Revit project; the automated browser test uses a simulated bridge.

## Startup and coexistence

1. Reload pyRevit and launch **MEPTools → HVAC Data** from a project. Verify the window title begins with HVAC Data and the window is modeless and independent, with Level, Number, Name, Area, and Height columns. Click Revit and verify it can cover the table. Restore the table through its taskbar/Alt+Tab entry and verify it remains usable; minimizing Revit must not force the table to minimize.
2. Verify saved-table controls appear on the left side of the header and Column groups, Parameters, and Refresh remain on the right with matching button height, font, and padding. The old FFE · MECHANICAL and Spaces heading must be absent. Check with and without Unsaved changes, at the normal/minimum window sizes and common display scaling settings; all controls must remain visible.
3. Launch it again for the same model, including while the window is minimized. Verify the existing window is restored and focused.
4. In fresh Revit sessions, test opening this tool before and after Keynotes and pyRevit's output window. All tools must continue working without mixed WebView2 assembly versions.
5. Disconnect the network and reopen the tool. Its local assets and full grid functionality must still load.
6. Launch with no document, a family document, and a project containing no Spaces. Verify a clear prompt or a valid empty table, without an unhandled exception.

## Data and units

1. Compare several rows with a Revit Space schedule: level, number, plain name, area, and unbounded height. Include leading-zero and alphanumeric numbers, repeated numbers on different phases, and non-English names.
2. Compare an imperial project and a metric project. Values must follow project formatting; sorting Area/Height must use numeric order. Change project units while the window is open, then Refresh.
3. Include placed, unplaced, unenclosed/redundant, and zero-area Spaces. All remain discoverable; zero is distinct from unavailable values, and row warnings explain missing data. An unreadable Space must not hide all remaining rows.
4. Verify the initial view phase, a view with no phase parameter, switching phases, All phases revealing the Phase column, and combined Phase/Level/search filtering.
5. Inspect a Space in RevitLookup whose `ROOM_PHASE_ID`/`ROOM_PHASE` references an existing project phase while `CreatedPhaseId` is invalid or different. Verify the table shows the spatial phase from `AsElementId()` and includes the Space when that phase is selected. Spaces with unreadable phase parameters must remain under All phases with a warning.

## Interaction and freshness

1. Open **Parameters…**. Compare the names and data types with RevitLookup on several Spaces, including built-in, project, shared, and unset instance parameters. Verify the catalog includes parameters found only on later Spaces. Same-named definitions must remain separate. The five starter parameters must be checked and locked, applied extra columns must be checked, and Phase must reflect whether its column is visible. Select/clear all must leave starter parameters checked and must not add duplicate starter columns.
2. Search by name or data type, select individual checkboxes and use the filtered header checkbox. Cancel and Escape must discard draft selections. Apply must add selected columns without changing the five starter columns or model data. Confirm Revit project formatting, numeric sorting, Yes/No labels, and reference names. Unavailable values must appear as an em dash with a row warning when reading fails.
3. Refresh after changing values, removing a selected parameter binding, and changing parameter names. Valid column selections, widths, sorting, filters, and selected rows must survive; removed columns must not leave an invalid sort. The picker remains usable at the minimum window size. Applying while another model is active must be disabled.
4. Verify the separate Parameter type column against built-in parameters, a bound shared parameter, and a non-shared project parameter. An unidentified definition must show Other. Toggle Show checked only: locked starter columns and checked additions must remain visible, unchecked items must disappear immediately, and search must intersect the checked filter and match parameter types. Clearing visible editable selections must preserve locked starter columns and selections outside the search. Cancel must discard drafts; Apply must retain selected parameters hidden by the picker filters. Check both the normal and minimum window sizes.

## Existing table behavior

1. Drag each starter column and added text, numeric, Yes/No, and reference parameter into the grouping area. Groups must show Revit-formatted values and the correct count of filtered Spaces. Verify zero and missing values, leading-zero numbers, same-named elements, duplicate parameter names, and parameter labels containing angle brackets.
2. Collapse/expand parent and child groups by clicking their headers and by focusing their buttons and pressing Enter/Space. Keyboard row navigation must skip all descendants of collapsed groups. Verify selection and Select/Show in Revit while grouped. Choose Clear all to restore the flat table.
3. Refresh and change filters while grouped. Grouping must remain selected when its columns stay visible. Remove a grouped parameter column, or hide Phase by selecting a single phase: remove only the affected level. Reordering columns must preserve the hierarchy. Check several thousand grouped rows and the minimum window size.
4. Drag Level, Name, and an added parameter into the dashed grouping area. Verify ordered chips connected by arrows and three matching nested levels, each with its own formatted label/count. Repeated header drops must never duplicate a level. Click the middle chip's ×: retain the other levels in order. Hide grouped Phase or remove a grouped parameter: remove only that level.
5. Drag grouping chips before/after each other and use Alt+Left/Right on a focused chip; hierarchy order must update without moving table columns. Drag headers onto the left/right halves of other headers to reorder columns without changing grouping. Click headers to sort and drag column edges to resize; neither action should start grouping. Cancel header and chip drags with Escape and release outside drop targets: preserve the layout. Repeat at the minimum window size and common Windows scaling settings. Verify arrows, chip removal, and Clear all remain usable when the grouping area wraps.
6. Save a table with at least three grouping levels, close/reopen it, and verify chips, hierarchy, and their order. Reorder just the chips and verify Unsaved changes, then save/reopen. Load an existing version 1 table: its single group must restore without a storage transaction; an explicit save upgrades it to the new format.

## General interaction

Right-click starter and added parameter headers, and a named band. Choose Change color, select light/dark/custom colors, and Apply. Confirm fills on headers and cells, readable text, unchanged sorters/selection, and visible row selection. Set a group color and a different child color: the child must keep its override. Reset the child to inherit the group; reset the group to restore defaults. Cancel/Escape must discard drafts. Check menu dismissal outside the menu and with Escape, and keyboard menu navigation. Move a colored column between groups, reorder whole bands, edit memberships/names, hide/show Phase, and Refresh: retain applicable colors. Save/Save As, close/reopen, and verify both column and band colors. A color-only change must mark Unsaved changes and participate in Save/Discard/Cancel. Old saved layouts must open with default colors and no storage write. Check the picker and menu at the minimum window size and common Windows scaling settings.

1. Open Column groups, add Dimensions, check Area/Height, and Apply. Verify a named band above both columns. Group nonadjacent columns and confirm they move together at the first member's position, with widths, sorting, selection, and row grouping preserved. Names containing angle brackets must display as literal text.
2. Add multiple bands, rename/edit membership, and Remove group. A column assigned to one band must be disabled in the others. Every band needs a nonblank name of at most 100 characters and at least one column. Cancel/Escape must discard the entire draft. Check the editor at the minimum window size.
3. Resize/sort grouped leaf headers and drag within/across bands. Cross-band drops must move the leaf into the target band; drops onto ungrouped columns must move it out. Verify row drag-to-group still uses the leaf column and never adds the band itself. Refresh after renaming/removing selected parameters: retain valid band members and remove empty bands. Hide/show Phase without losing its band membership.
4. Save/Save As a view with multiple bands containing built-in/shared/project columns. Reopen it and verify names, member order, widths, row grouping, and fresh values. A change to only a band name or membership must mark Unsaved changes and participate in Save/Discard/Cancel. Load older definitions without bands: retain their existing settings without creating storage writes.
5. Drag band titles before/after other bands and ungrouped columns. Verify the insertion marker, unchanged memberships, member order, widths, sorters, filters, row grouping, and selections. Drop onto another band's child: the entire source must land beside the entire target. Include hidden Phase among a band's members. Drop onto the same band or cancel with Escape: preserve the layout. A band must not become a row-group chip when dragged into the row grouping area.
6. Reorder bands by dragging, Refresh, then Save/Save As and reopen: retain the band order and all column settings. A successful band move must mark Unsaved changes; canceled drags must leave a clean view clean. Check at the minimum window size and common Windows scaling settings.

## Navigation and general interaction

1. Verify initial ordering by level elevation, then natural number order. Sort multiple columns, resize/reorder headers, and select a range of rows. Refresh must retain valid filters, sorting, column layout, and selection.
   Select a first sort, then Ctrl/Shift+click two more columns: verify priorities 1, 2, and 3 in selection order and actual rows ordered by the first key, then its ties by the second/third keys. Change the first key's direction without changing its priority. Remove a sort and verify renumbering; re-add it at the end. Switch to one column and clear sorting: remove badges immediately. Include added parameters and leaf headers inside named bands. Refresh and saved-table restoration must reproduce the priority order; unsorted columns and band titles must have no badges.
2. Verify Up/Down, Home/End, and Space after focusing the grid. Tab must reach filters and navigation buttons, with visible focus.
3. Select several rows and use Select in Revit. Show placed Spaces in a suitable plan/3D view. Try Show for unplaced Spaces and from a view that cannot display them; verify an actionable skipped/failure report.
4. Rename, add, or delete Spaces in Revit while the table is open. Verify Out of date appears and rows remain unchanged until Refresh. Try navigation to a deleted Space before Refresh; it must skip that row safely. Repeat after undo/redo.
5. Change a phase/level filter to hide a selected row. Navigation must act only on currently visible selected rows.
6. Test several thousand Spaces: scrolling should remain responsive, headers remain visible, and the grid should occupy available window space. Check both the default size and minimum window size at common Windows display scaling settings.

## Lifecycle and document safety

1. Open two projects, and open a separate table for each. Switching the active project must disable Refresh/Select/Show in the other table while leaving snapshot browsing available.
2. Queue navigation while Revit is busy, then switch documents before it executes. The request must fail clearly without navigating the other document.
3. Close one project and verify only its table closes. Repeat with Revit shutdown and with a table closed before a pending event executes. No event errors, orphan windows, or retained document actions should remain.
4. Reopen/close the table repeatedly, then edit the model. Verify no duplicated callbacks or stale windows appear.
5. In an otherwise unchanged project, use Refresh, sorting, filters, selection, and Show. Confirm this command does not mark the model modified or add transactions to Undo.

## Shared saved tables (Revit 2025 and 2026)

1. Open a model without saved definitions. Verify the initial Unsaved table and starter columns, with no new DataStorage element or model transaction until explicitly saving a definition.
2. Select built-in, shared, and project parameters. Reorder/resize columns, set multiple sorters, grouping, and phase/level/search filters. Save As a named table, Save/Sync Revit, close the project, and reopen. Select that definition and verify every setting plus current Space values. Row selections, collapsed groups, and picker display toggles must not be persisted.
3. Modify each layout setting and verify Unsaved changes. Switch tables or close the native window; verify Save/Discard/Cancel, including Save As for an unsaved table. A denied save must leave the same working view open and stop the original switch/close. Cancel the name dialog and verify nothing is saved or switched.
4. Save As a second definition, including one with the same name. Verify independent IDs and unambiguous picker labels. Rename while the working view is dirty: stored layout and working changes must be preserved. Delete with confirmation: only that definition disappears; the current working table and all Spaces remain.
5. Rename a shared/project parameter, and reopen its table. Verify persistent identity resolves it. Remove a selected parameter binding, phase, or level and verify warnings, safe fallbacks, and cleared dependent grouping/sorting. A same-named replacement with a different identity must not substitute silently. Confirm the original definition remains stored until explicitly saving the repaired view.
6. With two workshared users, create two definitions and sync/reload them. One user edits/owns table A while the other edits table B: they should not require ownership of a shared catalog element. Try modifying owned table A, a definition updated in central but not reloaded, and a stale revision after Reload Latest. Updates must be rejected without replacing working changes. Save As must remain available when the original is owned or stale.
7. Open a read-only model: load/browse definitions and verify writes are disabled. Exercise save/rename/delete failure paths and confirm transactions do not remain open. Save/rename/delete must change only table DataStorage, with clear Undo entries; normal browsing remains read-only.
8. Refresh after another user renames, updates, or deletes an active definition. The catalog must refresh without silently replacing the current view or loaded revision; attempts to update a stale or deleted definition must fail safely. Reopen or Save As to reconcile. Verify unsupported/corrupt saved definitions are reported and preserved while valid tables remain usable.
9. Close the document or Revit while a tool dialog/request is pending. The table must release its resources without writing to an invalid document. Repeat startup/coexistence and minimum-window checks with saved-table controls visible.
